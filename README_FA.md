# SQL Server Simulator v0.6.1 | راهنمای استفاده

**طراحی و ساخت: علی صیادی**  
**گزارش خطا:** `Ali.sayyadi200@gmail.com`  
**توجه:** این نسخه آزمایشی است و ممکن است اشکال داشته باشد. قبل از تغییر ساختار جدول‌ها از فایل `.db` نسخه پشتیبان بگیرید.

## رفع دو ایراد گزارش‌شده در نسخه 0.6.1

- **اتصال مستقیم کار می‌کند:** در Diagram دکمه `Draw Link (2 clicks)` را روشن کنید و روی ردیف کلید اصلی جدول والد و سپس روی ردیف FK فرزند کلیک کنید. خط راهنمای ماوس دیگر روی فیلد مقصد نمی‌افتد و کلیک دوم را مسدود نمی‌کند. با کشیدن ردیف فیلد اول به ردیف فیلد دوم نیز Wizard باز می‌شود.
- **مقیاس واضح:** پس از باز شدن جدول‌ها، فیلدها در اندازه ۱۰۰٪ نمایش داده می‌شوند و به‌اندازه غیرقابل‌کلیک کوچک نمی‌شوند. برای نمای کامل از `Fit Diagram` و برای کار دقیق از `100%` استفاده کنید. پس از انتخاب فیلد اول، پیام «Step 2/2» ظاهر می‌شود؛ با زدن Esc لغو کنید.
- **خوش‌آمدگویی بدون برش:** ارتفاع متن، فاصله‌ها و اندازه فونت اصلاح شده‌اند. در پنجره کوچک صفحه خوش‌آمدگویی اسکرول عمودی دارد.
- **تست جدید Qt:** اتصال دوکلیکی و drag واقعی با شبیه‌سازی رویدادهای ماوس، به همراه بررسی ارتفاع عنوان در تم روشن/تاریک، در مرحله CHECK ویندوز اجرا می‌شود.

## تغییرات اصلی نسخه 0.6

- **انتخاب رابطه:** در Database Diagram روی خط FK، علامت یا نام رابطه کلیک کنید؛ خط انتخاب‌شده با رنگ مشخص نمایش داده می‌شود و جزئیات آن در Properties قابل مشاهده است.
- **حذف رابطه:** روی خط راست‌کلیک کرده و `Delete Relationship...` را انتخاب کنید؛ یا دکمه `Delete Link` را بزنید؛ یا پس از انتخاب خط کلید Delete را فشار دهید. پس از تأیید، **محدودیت واقعی FK** حذف می‌شود و دیگر جلوی درج مقادیر نامعتبر را نمی‌گیرد. جدول، ستون و رکورد پاک نمی‌شوند.
- **رابطه چندبه‌چند:** اگر خط‌چین `N:M via <bridge>` را انتخاب و حذف کنید، هر دو FK جدول واسط در یک بازسازی تراکنشی برداشته می‌شوند. **جدول واسط و اطلاعاتش باقی می‌مانند.** اگر فقط یکی از خطوط واقعی FK را حذف کنید، فقط همان FK حذف می‌شود و نمودار دیگر رابطه کامل N:M را نشان نخواهد داد.
- **ترسیم دستی:** دکمه `Draw Link (2 clicks)` را فعال کنید. یک بار روی فیلد PK والد و بار دوم روی فیلد FK فرزند کلیک کنید. پنجره Wizard باز می‌شود و محدودیت‌های PK/FK، انواع داده و جامعیت ارجاعی بررسی می‌شوند. برای لغو Esc را بزنید. قابلیت کشیدن مستقیم فیلدها نیز همچنان وجود دارد.
- **صفحه خوش‌آمدگویی:** چیدمان جدید قابل‌پیمایش و واکنش‌گرا است؛ عنوان، توضیحات، نام سازنده، هشدار نسخه آزمایشی و دکمه Gmail در قسمت‌های جداگانه‌اند. نمایش RTL فارسی از نمایش انگلیسی تفکیک شده است.

## اجرای سریع

1. ZIP کامل را در یک **پوشه جدید** استخراج کنید.
2. `run_windows.bat` را اجرا کنید. برای بار اول به اینترنت نیاز خواهید داشت.
3. برای ساخت فایل EXE پس از آزمایش برنامه، `build_windows.bat` را اجرا کنید. نصب‌کننده Setup به Inno Setup 6 نیاز دارد.
4. اگر ساخت EXE توسط آنتی‌ویروس مسدود شد، آنتی‌ویروس را غیرفعال نکنید؛ از طریق فایل `run_windows.bat` آزمایش کنید و Protection History ویندوز را بررسی کنید.

**محدودیت:** این برنامه برای آموزش طراحی رابطه از SQLite استفاده می‌کند؛ خود SQL Server نیست و همه قابلیت‌های SSMS را ندارد.

# SQL Server Simulator v0.6.1 | محیط آموزشی ویندوز

**طراح و سازنده: علی صیادی**  
**گزارش اشکال:** `Ali.sayyadi200@gmail.com`، منوی Help > Report a bug via Gmail

این برنامه مستقل از Microsoft SQL Server و با Qt / PySide6 ساخته شده و از SQLite به‌عنوان موتور واقعی پایگاه داده استفاده می‌کند. هدف آن آموزش طراحی جدول، PK/FK، ارتباطات و نمایش ERD به سبک SSMS است. این ابزار همه قابلیت‌های Microsoft SSMS یا T-SQL را ندارد و وابسته یا منتسب به مایکروسافت نیست. این نسخه اولیه ممکن است اشکال داشته باشد.

## اجرا در ویندوز 10/11

1. کل ZIP را در پوشه جدیدی مثل `G:\project\projectSQL\SQL_Server_Simulator_v0_6_1` استخراج کنید.
2. **ابتدا `run_windows.bat` را اجرا کنید** و محیط گرافیکی را آزمایش کنید. اسکریپت، Python نصب‌شده را پیدا و محیط مجازی مخصوص برنامه را آماده می‌کند؛ برای نصب اولیه پکیج‌ها به اینترنت نیاز است.
3. برای ساخت نسخه قابل‌حمل در قالب پوشه EXE، فایل **`build_windows.bat`** را اجرا کنید. این فایل اول آزمون‌های پایگاه داده و رابط Qt را اجرا می‌کند؛ سپس PyInstaller را فراخوانی می‌کند.
4. فایل ساخته‌شده: `dist\SQLServerSimulator\SQLServerSimulator.exe`؛ **پوشه `SQLServerSimulator` را کامل نگه دارید.**
5. برای تولید نصب‌کننده گرافیکی Setup، باید **Inno Setup 6** نیز نصب باشد. خروجی در صورت موفقیت: `installer_out\SQL_Server_Simulator_Setup_v0.6.1.exe`. این Setup از قبل داخل ZIP نیست.
6. اگر نسخه قبلی نصب شده است، بهتر است این نسخه را در پوشه‌ای **مجزا** استخراج کنید. فایل‌های پروژه `.db` قبلی با File > Open Database قابل باز کردن هستند. **قبل از ویرایش جداول مهم از فایل دیتابیس کپی بگیرید.**

## امکانات جدید 0.5: اتصال ستون‌ها و بستن پنجره‌ها

- در **Database Diagram** از **ردیف یک فیلد PK** به **ردیف فیلد FK جدول فرزند** بکشید و رها کنید؛ بدون روشن‌کردن Connect by Drag نیز کار می‌کند. برای جابه‌جاکردن جدول، **سرعنوان کارت** را بکشید، نه ردیف فیلد را.
- پنجره **Field Mapping Wizard** باز می‌شود: جدول والد، ستون PK، جدول فرزند، ستون FK و نوع رابطه را بررسی کنید. رابطه 1:N به FK واقعی تبدیل می‌شود؛ برای N:M باید از فیلد PK هر دو جدول استفاده و نوع N:M را انتخاب کنید تا جدول واسط ساخته شود.
- می‌توانید فیلد موجود را انتخاب کنید یا گزینه **Create new foreign-key field** را بزنید. فیلدهای نامعتبر از جمله نوع داده ناسازگار یا مقدار یتیم، قبل از تغییر ساختار با پیام مشخص رد می‌شوند.
- برای 1:1 کلید اصلی فرزند باید مشترک و بدون Identity باشد. برای SELF فیلد FK باید از PK همان جدول مجزا باشد. NULL برای FK اختیاری مجاز است؛ اگر Required فعال باشد، NULL رد می‌شود.
- برای پنهان کردن کارت یک جدول در نمودار روی **× در گوشه کارت** کلیک کنید یا **راست‌کلیک > Close table in diagram**. این کار **فقط نمایش را می‌بندد** و هیچ جدولی را از پایگاه داده حذف نمی‌کند.
- برای بازگرداندن جدول‌ها **Reopen Tables** را در نوار نمودار یا **راست‌کلیک > Reopen hidden table** انتخاب کنید. پس از Refresh، وضعیت پنهان‌بودن جدول‌ها حفظ می‌شود.
- برای بستن صفحه نمایش اطلاعات جدول روی **× تب** یا دکمه **Close View** در بالای آن کلیک کنید. پنجره‌های Design و Wizard دکمه Cancel و × پنجره دارند.

## قابلیت‌های حفظ‌شده از 0.4

### 1. راست‌کلیک / Design Table
- از **Object Explorer** روی نام جدول راست‌کلیک و **Design Table…** را انتخاب کنید؛ یا از بخش **Database Diagram** روی کارت جدول **دو بار کلیک** کنید، یا **راست‌کلیک > Design Table**.
- می‌توان ستون جدید اضافه کرد، نام ستون موجود را تغییر داد، نوع داده `NVARCHAR(50)` و سایر انواع را انتخاب کرد، nullable و PK را تغییر داد و مشخصات `IDENTITY(seed, increment)` را دید و تنظیم کرد.
- داده‌های ستون‌های **تغییرنام‌داده‌شده** هنگام بازطراحی به‌صورت تراکنشی منتقل می‌شوند. اگر محدودیت طول، کلید خارجی، کلید اصلی و... نقض شوند، عملیات رد می‌شود و ساختار قبلی باقی می‌ماند.
- حذف ستون موجود می‌تواند داده‌های آن را پاک کند و هشدار دارد. تغییر ستون دارای default، trigger/index سفارشی یا تغییر نام PK مرجع در حالت بصری عمداً محدود شده تا داده آسیب نبیند.

### 2. Database Diagram تعاملی
- **New Table** در نوار بالای دیاگرام، یا **راست‌کلیک فضای خالی > New Table…** جدول جدید می‌سازد.
- برای اتصال از کارت جدول به کارت دیگر، **Connect by Drag** را فعال کنید. از کارت جدول **والد (سمت یک)** به کارت جدول **فرزند (سمت چند)** بکشید؛ **Relationship Wizard** با جداول انتخاب‌شده باز می‌شود. برای رابطه بازگشتی از همان جدول به خودش بکشید.
- اگر کشیدن اتصال را ترجیح نمی‌دهید، روی جدول **راست‌کلیک > New Relationship from…** بزنید یا روی **Relationship Wizard** کلیک کنید. برای بازگشتی، گزینه راست‌کلیک **Self-referencing relationship…** نیز وجود دارد.
- نوع رابطه را در Wizard انتخاب کنید: **1:1** با PK مشترک، **1:N** با FK در فرزند، **N:M** با ایجاد جدول واسط، یا **SELF** (سلسله‌مراتب 1:N همان جدول).
- در N:M یک جدول واسط واقعی ساخته می‌شود. می‌توان PK ترکیبی دو FK یا PK مستقل Identity همراه UNIQUE(FK1,FK2) را انتخاب کرد. دیاگرام دو اتصال واقعی 1:N به جدول واسط را نشان می‌دهد و یک خط چین `N:M via bridge` به‌عنوان نمایش مفهوم کلی اضافه می‌کند.
- نشانه‌های 1/N/M و انتهای رابطه روی خطوط، برای توضیح کاردینالیتی نمایش داده می‌شوند. مکان کارت‌های جدول ذخیره می‌شود؛ Ctrl+Wheel بزرگ‌نمایی دارد.

### 3. جامعیت ارجاعی واقعی
- کلید خارجی **غیر NULL** حتماً باید به رکورد موجود در کلید مرجع اشاره کند. درج، ویرایش یا حذف نامعتبر توسط موتور پایگاه داده رد می‌شود.
- در SELF فیلد `ManagerID` یا `ParentID` به PK همان جدول اشاره می‌کند. `NULL` برای ریشه سلسله‌مراتب مجاز است.
- از منوی **Database > Check Referential Integrity…** می‌توانید همه FKها را بررسی کنید. در Query Editor امکان خاموش‌کردن تنظیمات کنترل FK/Check عمداً مسدود شده است.
- رابطه 1:1 با اشتراک کلید، یکتایی و وجود مرجع را تضمین می‌کند، ولی اجبار داشتن یک فرزند برای هر والد را تضمین نمی‌کند.

### 4. پایگاه داده آماده آموزش
- فایل `examples\Diagram_Training_v0_4.db` را با **File > Open Database** باز کنید. این مثال پنج جدول دارد: `Department`, `Student`, `Profile`, `Course`, `Enrollment`. روابط `1:1`, `1:N`, `N:M` و خودارجاعی `Student.MentorID` از قبل ساخته و رکوردهای نمونه وارد شده‌اند.
- امکان **Create Teaching Sample** روی پایگاه داده جدید و خالی نیز وجود دارد.

## سایر قابلیت‌های قبلی
- New Database Wizard، تنظیم Data Type، IDENTITY seed/increment، فرم درج اطلاعات و Edit Rows، Query Editor، تم روشن/تاریک، انگلیسی پیش‌فرض با انتخاب فارسی، خروجی PNG نمودار.
- **Generate SQL Server Scripts** با انتخاب جدول، ساختار/داده و نسخه هدف 2012 تا 2025. فایل خروجی `.sql` است، **نه `.bak` واقعی**. سازگاری کامل T-SQL یا اجرای موفق روی تک‌تک نسخه‌ها تضمین نشده است.
- ذخیره و ورود داده بر پایه SQLite است؛ رفتارهای نوع داده و محاسبه IDENTITY ممکن است در جزئیات با SQL Server متفاوت باشند.
